2. Wrapper 与 Linker 的接口边界

UnifiedCacheLinkerWrapper 是 SGLang 已实现的 Tree 侧编排器；外部 Backend 只需要实现 UnifiedCacheLinker 抽象接口，不应重新实现 Wrapper。

UnifiedCacheLinkerWrapper（SGLang 提供）

持有 cache 与 cache_linker；理解 Radix Tree、TreeComponent、node lock、TP/CP 同步和 pending 状态；把 Tree 操作翻译成 Backend 调用。

UnifiedCacheLinker（Backend 实现）

不接触 TreeNode；只理解 PoolTransfer、rid、物理 key/指针、异步 I/O、layer completion 与完成结果。Mooncake、UMBP、UCM 都实现这一侧。

4. Lookup / Match：只查询，不分配 Device slot

输出是可恢复长度与 hit marker；Tree 还没有插入 L3 tail。

① Radix L1 match得到 result.device_indices、last_device_node 和 device hit 长度。
② Wrapper._tail_hashes以最后一个 L1 hash 为 anchor，对未命中且 page 对齐的 tail 生成 storage hashes。
③ TreeComponent每个 component 构造 LOOKUP PoolTransfer；任一必要 transfer 缺失则放弃 L3 hit。
④ backend.lookuplookup(rid, transfers) 返回本 rank 稀疏的 restorable page set。
⑤ 跨 rank 交集0/1 mask + MIN all-reduce，选择所有 rank 共同支持的最长边界。
⑥ 发布 MatchResult保存 hit_markers[rid]，设置 host/swa/mamba hit length；不执行 I/O。

ExternalCacheHitMarker

prefix_key：L1 prefix + 可恢复 tail
tail_hashes：仅 tail 的 page hashes
device_hit_len：已有 L1 token 数

重要结果

lookup() 的返回不是“KV 最大命中数”，而是所有必要 Pool 在精确边界上均可恢复的页数集合。

6. Dump / Offload：Tree action 驱动的异步写穿

抽象接口称为 offload；是否逐层 dump、对象布局和协议由具体 backend 决定，Linker 契约本身没有逐层 offload counter。

① BackupKV actionTree write-through chain 产生待持久化 node_ids。
② 构造 transfersbuild_external_linker_offload_transfers(node_id)；已 stored/pending 的 node 被跳过。
③ 加 node lock保证 dump 读取期间 device slot 不被 allocator 回收或复用。
④ backend.offloadoffload(transfers) → bool；True 只表示成功入队。
⑤ 标记 pendingwrite_through_pending_id=node_id，记录 FIFO pending_offloads。
⑥ 最终完成pop_completed_offload() 后调用 finish_external_linker_offload(..., success) 并释放 lock。
不要混淆：offload() == True 是“任务已接受”；只有 pop_completed_offload() == True 才能令 external_cache_stored=True。Node split 时，Wrapper 会把 ack 的发布目标替换成 split 后的新 node IDs。

7. Node 状态与双完成信号

Load 与 Offload 都锁 node，但发布的状态不同。

Offload 状态机

L1 onlystored=False
pending=None
Offload pendingstored=False
pending=ack_id
node locked
L3 confirmed / failed成功：stored=True
失败：stored=False
两者均清 pending、释放 lock

Load 的两个“完成”

逐层完成：layer_done_counter

Backend 每完成一层 L3→Device，就推进 counter/event；Forward 只需等待当前层，支持 I/O 与计算流水。

整批完成：completed_loads

所有请求/层传输结束后，Backend 把 rid batch 放入完成队列；Wrapper 消费后释放 endpoint node locks。
