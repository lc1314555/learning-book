MooncakeDirectLinker 调用实现图

展开 Mooncake 对 UnifiedCacheLinker 契约的具体实现：GPU buffer 注册、PoolTransfer 展开、同步 lookup、异步逐层 load、异步 dump/offload，以及两条完成队列。

实现图 · 独立于抽象接口图
物理路径：MooncakeDirectLinker 将 Device Pool buffer 直接注册给 Mooncake。Load 使用多 buffer range GET 写入 GPU 地址；Dump 使用 batch_set_v2 从 GPU buffer 写入 Mooncake，不经过 SGLang HostPool。

2. Lookup：同步调用 MooncakeStore

发生在 scheduler match 路径，直接影响调度延迟。

① lookup(rid, transfers)输入是 Wrapper 构造的每 component PoolTransfer。
② resolve_transferspool_group.resolve_transfers(transfers) 将逻辑 transfer 展开为实际 pool/layout transfer。
③ batch_exists_v2以 KV page keys 为逻辑 anchor，按各 Pool 的 component keys 查询对象存在性。
④ hit policyALL_PAGES 检查连续前缀；TRAILING_PAGES 检查目标边界尾窗/状态对象。
⑤ restorable_prefix_pages返回本 rank 可完整恢复的稀疏边界集合给 Wrapper。
转换输入输出作用
_get_hybrid_page_component_keyspage keys + transferphysical component keys + multiplier把一个逻辑 page key 展开为具体 pool/component 对象 key。
_tag_keyscomponent keys带 config prefix 的 keys隔离模型/配置命名空间。
batch_exists_v2KV keys + expanded transfersPoolTransferResult综合所有 pool 的存在性，计算可恢复边界。
