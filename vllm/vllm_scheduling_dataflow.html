◆4. 抢占与 KV 分配（重点）

核心机制：allocate_slots() 若拿不到足够空闲 block 会返回 None，调度器随即驱逐一个 running 请求（抢占），把它降回 waiting 并释放其 KV block。这是 vLLM 在显存受限下保证持续吞吐的关键。

分配

空闲 block 由 BlockPool 的 free_block_queue 提供，分配即从空闲队列取出并增加引用计数。

◆5. 数据传输：L1 / L2 / L3（重点）

◆6. L3 = UCM 传输详解

◆7. 端到端案例：命中 L3 的请求

假设请求的 prompt 前段此前已被别的请求写入 L3（UCM），本请求可跳过这部分的计算。

sequenceDiagram autonumber participant U as 用户请求 participant S as Scheduler participant KV as KVCacheManager participant UC as UCM participant W as Worker U->>S: add_request S->>KV: 本地 prefix cache 命中 = 0 S->>UC: get_num_new_matched_tokens() UC-->>S: 命中 3 个 block（L3） S->>KV: allocate_slots(含命中 block) S->>UC: build_connector_meta(load 这些 block) S->>W: SchedulerOutput W->>UC: start_load_kv() L3→L1 W->>W: forward 仅计算未命中部分 W->>UC: wait_for_save() 新 KV 落盘 L3 W-->>S: ModelRunnerOutput S-->>U: Stream 输出 token
收益：L3 命中把「重算 prefill」变成「读 KV」，用外部存储换计算。代价是加载延迟——因此用 persist_token_threshold / load_blocks_threshold 过滤小请求/小命中。
